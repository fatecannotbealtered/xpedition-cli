# xpedition-cli capability summary

Generated from the product registry. Parameters and result shapes come from `reference` at run time; this is not an authorization policy or verification evidence.

| Command | Type | Effects | Maturity | What it does |
|---|---|---|---|---|
| `bom check` | read | observe | draft | Problems in the bill of materials: parts without a part number, repeated reference designators, and one part number used with different values or packages |
| `bom export` | write | artifact | draft | Write the schematic bill of materials to an explicit JSON file. |
| `bom inspect` | read | observe | draft | Read the schematic bill of materials; optionally group rows or compare a baseline. Use bom export to create a file. |
| `changelog` | read | observe | draft | Version changes from the embedded CHANGELOG; --since returns only newer versions. |
| `context` | read | observe | draft | CLI, adapter, running service and application identity, the task scope and the record store. |
| `doctor` | read | observe | draft | Readiness checks (release readiness, task scope, native backend, record store), each failure with a fix. |
| `kb bind` | write, dangerous | configure, persist | draft | Bind a knowledge-base document's link under a name, with what it covers; binding a name again re-points it |
| `kb list` | read | observe | draft | The knowledge-base documents bound on this machine: a name, a link and what each covers. The agent reads them with its own tools |
| `kb unbind` | write, dangerous | configure, persist | draft | Unbind a knowledge-base document |
| `library check` | read | observe | draft | Check the central library: parts against their cells, symbols and pin maps, cells against the padstacks and for silkscreen over their lands, symbols with repeated pin names, part numbers in two partitions; most severe first. LMC registration is observed separately from an active matching LibraryManager; an unavailable observation does not prove registration or packager usability |
| `library create` | write, dangerous | session, change, persist | draft | Add parts to the central library from a parts file: each part's symbol (a box or a built-in kind), footprint (an IPC-7351B family from datasheet dimensions, lands given one by one -- several may share a pin, holes may be slots or unplated --, a placeholder package or a cell the library holds) and pin map. What the library holds already is left alone when identical. Native writes preflight registered partitions for kept and changed dependencies |
| `library import` | write, dangerous | session, change, persist | draft | Import parts from another Xpedition central library -- another project's, or a copy of a company library -- with the symbols, cells, padstacks, pads and holes they use, each in its source partition. The source is only read; what the library holds identically is left alone. Native writes require registered partitions for the full resolved dependency closure, including kept items |
| `library inspect` | read | observe | draft | One part in full -- pin map, symbol pins, cell lands and their padstacks, and what is wrong with it -- or one cell and the parts that use it |
| `library list` | read | observe | draft | What the project's central library holds, one kind at a time: parts, cells, symbols or padstacks, read through the stock converters (cached until a database changes) |
| `library materialize` | write | session, change, persist | draft | Materialize the missing placeholder padstacks, cells and parts required by a design. This does not run schematic packaging; use schematic package as a separate operation. |
| `library preview` | write | artifact | draft | A PNG per part, its symbol beside its footprint (lands numbered, silkscreen, assembly and placement outlines, a 1 mm bar): from the library, or from a parts file before it is added |
| `manufacturing export` | write | session, change, persist, artifact | draft | The fabrication package: Layout's ODB++, Gerber (RS-274X) and NC drill outputs, copied into one folder with a centroid file, a BOM and a manifest of checks |
| `manufacturing verify` | read | observe | draft | Independently verify manifest paths, file sizes and SHA-256 values. This integrity suite does not provide CAM geometry, DFM or manufacturing sign-off. |
| `operation list` | read | observe | draft | Recent operation records from the local store, newest first. |
| `operation resolve` | read | observe | draft | Record what an independent read-back showed about an unknown or partial operation; changes only the local record, needs the scope that allowed the operation and refuses while the operation is still running. |
| `operation show` | read | observe | draft | One operation record: plan, status, receipt and resolution. |
| `pcb checks result` | read | observe | draft | Read one retained PCB check run, or hash-verify and parse historical native files with --native-files. No native checker is executed. Historical parsing does not establish native completion, freshness or hazard matching. |
| `pcb checks run` | write | change, persist, artifact | draft | Run a new bound Layout Batch DRC and derived board-rules check. Saves/closes the board, runs the registered engine once, writes native configurations/reports, then reopens. Preview names the known report, setup, staging and lifecycle-log paths; other native side effects remain unclassified. A completed report can contain violations; ignored rules are retained. Unproven native completion remains incomplete; read its retained report with pcb checks result. |
| `pcb constraints widths` | write | change, persist | draft | Preview the requested net-class creation/selection, net assignment, all three trace-width fields on every layer and Layout synchronization. This full command has no verified native write contract: can_apply=false; offline preview observes no native state and confirmation refuses before COM attachment or writes. A single IConstraint.Value PUT cannot validate the whole command. See docs/CURRENT-CANDIDATE.md for current evidence. |
| `pcb copper pour` | write | session, change, persist | draft | Create one new bounded plane on an empty rectangular signal-layer board, generate only its net/layer assignment, verify actual copper/voids and protected objects before saving, then normally close/reopen and compare. Explicit net/layer required; existing planes, vias/slots, replacement and removal are unsupported. Full thermal/tie conductor geometry lacks independent proof; native connectivity, DRC execution and persistence are separate evidence. |
| `pcb copper remove` | write | session, change, persist | draft | Reserved existing leaf: copper removal is currently unsupported and refused before native writes. |
| `pcb create` | write, dangerous | session, change, persist | draft | Create the project's board from a layout template of its central library through JobWizard |
| `pcb diagnostics close` | write | session, persist, artifact | draft | Review-only diagnostic on a fresh authenticated closed-backup copy and owned Layout. One bounded Save and Close(True); no engine, Go, Open or retry. Unknown terminal stops without CAD queries. Only returned terminal permits two bound identity/file frames; never qualifies save/reopen or PCB acceptance. |
| `pcb holes add-corners` | write | change, persist | draft | A non-plated mounting hole in each corner of the board outline |
| `pcb inspect` | read | observe | draft | The board in numbers, with its stackup (each layer's kind, name, thickness and dielectric constant), its net classes (nets and trace widths per layer, separate class/member read completeness and located getter errors) and how many keepouts it has; native library cell names and the hosted active database object are reported separately. Failed reads are not observed empty membership. --live-geometry with explicit --pid observes the already-open matching board's full measured geometry without save/open/switch or operation reconciliation; historical saving remains unknown. With exactly one --nets name and one --layers number it also reads complete native routepass state/material evidence on that same document, without routing. --components queries arbitrary observed net material components with snapshot-scoped selection IDs; complete observation is distinct from whole-net connection. --continue-existing observes the limited GND components separately from whole-net completion; complete observation can report incomplete connectivity |
| `pcb metrics` | write | observe, artifact | draft | How good the placement and routing are, as numbers to compare two states by: ratsnest length and crossings, overlaps, parts off the board, decoupling distances, connector-to-edge distances, density, trace length, vias and acute corners; --baseline compares with an earlier result. From a geometry file, or the live board with --project |
| `pcb outline set` | write | change, persist | draft | Replace the board outline by a width x height millimetre rectangle from the origin, optionally with rounded corners |
| `pcb placement auto` | write, dangerous | change, persist | draft | A first placement of the board's unplaced parts that follows the connections: one cluster per sheet, zone labels on the top silkscreen. With --all the placed parts move too |
| `pcb placement move` | write | change, persist | draft | Move parts: one to a position and rotation (--refdes, --to, --rotate), or a selection by translate, rotate, align and distribute steps (--file); every move is read back |
| `pcb render` | write | artifact | draft | A PNG of the board drawn from its geometry (outline, pads, traces, vias, planes, holes, silkscreen and its designators as Layout strokes them); --refdes draws only those parts and what is around them, larger; needs no screen, so it works with the desktop locked |
| `pcb routing apply` | write | change, persist | draft | Unsupported in this candidate: the legacy routing path lacks bounded copper impact and pre-save protection proof. Refuses before native route/regeneration/save calls; use pcb routing trace preview for explicit blockers. |
| `pcb routing auto` | write, dangerous | change, persist | draft | Use --mode bounded-native for one exactly selected, unrouted two-/three-pin net or the exact six-pin GND member set on one signal layer through the native NoViaPass engine. Bounded-general instead requires --file and freezes a unique unconnected FromTo and all actual native settings for one formal General Route35367 candidate, permitting only predeclared target-GND old-copper replacements in a finite rectangle. Explicit --continue-existing instead binds only the six-pin GND with three old target traces, three material groups and two opens; every old trace identity and raw path must remain exact. Preview binds the real board, members, readable rule observations and configuration intent; opaque database/cache versions and atomic freeze are unproved. Independently verify all new trace segments, pad-material contact and protected objects before strict Save/Close/Open. The default legacy auto mode remains unsupported. Native solver acceptance does not establish complete effective-rule parsing or DRC. |
| `pcb routing stitch-plan` | write | observe, artifact | draft | The plan for ground stitching: a via beside every surface-mount pad of a net with a short stub, where the clearance check against a geometry file finds room. Works from pcb snapshot's file; feed the plan to pcb routing apply --file |
| `pcb routing trace` | write | session, change, persist, artifact | draft | Preview one explicitly named net, signal layer, mm path and width on the exact already-open board. Default trace mode requires exactly two physical pins, one open and no existing routing. Bind endpoint/pad ownership, geometry, inputs, rules and possible copper impact before mutation. Named-width diagnostics retain class and member read completeness and located getter errors; failed reads are not observed empty membership. Current native rule applicability and bounded copper-change proof are unavailable: can_apply=false and confirmation refuses before routing, regeneration or Save/Close/Open. No dangerous override. Explicit component-connect mode instead binds an exact --component-query snapshot, two component/node choices and an isolated-origin record to one native DRC transaction. Complete actual material and old-object protection precede conditional persistence. Same-component tasks are no-ops without apply or Save. Full effective-rule parsing and manufacturing acceptance remain unproved. |
| `pcb routing unroute` | write, dangerous | session, change, persist | draft | Remove the bound native traces/vias of explicit whole nets, preserve other objects, then save/close/reopen and independently compare. Verified scope: two separated physical pins per net without planes; --all/--at/--layer are currently refused. Expected disconnects are operation success, not engineering routing completion |
| `pcb routing via` | write | change, persist | draft | Unsupported in this candidate: the legacy routing path lacks bounded copper impact and pre-save protection proof. Refuses before native route/regeneration/save calls; use pcb routing trace preview for explicit blockers. |
| `pcb silkscreen labels` | write | session, change, persist | draft | Move uniquely identified existing silk reference texts to explicit mm positions with --file; bind actual owner/UID/fabrication Type/Side/SideName/envelope and raw soldermask stackup association; protect every other captured object before conditional save/close/reopen. Legacy automatic/size preview remains available but confirmation is disabled |
| `pcb snapshot` | write | observe, artifact | draft | The board as data: outline, parts with their origin, extents and pins, pads with net, layer and pin, traces with width, vias, planes, holes, keepouts, open nets, silkscreen, and its texts with their part, box and strokes; --refdes and --nets keep only what they name, the parts' silkscreen with them; to a JSON file with --output |
| `pcb update` | write, dangerous | change, persist | draft | Forward-annotate the packaged schematic into the board: its parts and nets replace the board's, and the board is saved. Verification covers part/pin/net correspondence. With --refresh-cells, refresh central/local cell definitions and existing instance geometry instead; logical in_synch alone is insufficient |
| `pcb view` | write | session, artifact | draft | Observe and apply a file-bound local display scheme, fit the board or selected parts, and optionally capture a new PNG. Preview binds Config sources and lists layout reminders; verification separates effective scheme, viewport, visibility, foreground and image decoding from visual review. |
| `project backup` | write | session, persist, artifact | draft | Preview complete read-only library/Designer/Layout release identities; unknown writers refuse before confirmation. Recheck frozen identities before saving/closing matching owned documents, then archive every project file with hashes. Outside projects remain untouched; no forced release. |
| `project create` | write | session, change, persist | draft | Create an owned project: clone an initialized template or initialize a stock setup template through native NewProject, then reopen and inspect it. Explicit --closed-copy instead copies every verified closed-backup member of an initialized source into a new disjoint ASCII directory, relocates only public PRJ library keys and independently verifies all copied bytes. It never calls native applications, initializes a library/PCB or opens the result; complete byte copying is not native openability or production acceptance. |
| `project inspect` | read | observe | draft | What a .prj says, read from the file itself: its designs, board, central library and the libraries each design lists. --preflight instead queries finite design/verification/environment capabilities before design, with optional declared --requirements JSON; this does not observe CAD or authorize dispatch |
| `project restore` | write, dangerous | session, change, persist | draft | Make the project folder what a backup holds: the dry run lists the files it adds, replaces and removes; the confirmed run closes the project, zips the folder as it is first, restores and opens the project again |
| `reference` | read | observe | draft | This reference. --index lists one line per command; --command <path> returns one command. |
| `schematic build` | write, dangerous | change, persist | draft | Plan a schematic from a design description and draw it in Designer, then read the netlist back and compare it with the plan. Each sheet drawn is wiped first; --sheets draws only those (to resume a draw that stopped). Read drawing_review for planned projection checks and missing native drawing coverage |
| `schematic checks result` | read | observe | draft | Read one retained schematic check run; no native checker is executed. Stale and incomplete reports remain labelled. |
| `schematic checks run` | write | change, artifact | draft | Run Designer verification and derived netlist rules, retaining a report bound to this run. Native completion and rule coverage are reported separately. |
| `schematic edit` | write | change, persist | draft | Change a drawn schematic in place from an operations file: place, move or delete a part, set a part's property, create a net, connect or disconnect a pin, rename a labelled net. The dry run checks every operation against the design. Optional set_property.display moves one existing Value or Part Label attribute (integer sheet-unit x/y, visible:true=VDVALUEVISIBLE3, optional integer Size5..30); horizontal actual getters and unique existing attributes are required. Display-only batches verify protected records before one SaveAll, normally close/reopen this project, then read identity and records again. The confirmed run reads the design back and verifies it. drawing_review lists affected objects and visual rules not checked because native text envelopes, graphics, wire paths and sheet bounds are not observed |
| `schematic export` | write | artifact | draft | Render the schematic to a new PDF through Xpedition's sch2pdf and report each page's size and orientation. Before confirmation, drawing_review discloses that the Designer drawing model and visual-check inputs were not read |
| `schematic nets` | read | observe | draft | The schematic's nets: name, kind (power, ground or signal), sheets and the pins each joins |
| `schematic package` | write | change, persist | draft | Package an existing schematic for PCB integration; library materialization is a separate operation. |
| `schematic parts` | read | observe | draft | The schematic's parts: reference designator, part number, value, sheet, attributes and every pin with its net; limited named attribute_display getter records retain position, Visible, Size, Orientation, Origin and read failures in sheet units, with incomplete free-text/font-envelope coverage |
| `schematic plan preview` | write | artifact | draft | Validate preview inputs and report planned layout findings before confirmation; a PNG of every planned sheet of a design, drawn from the plan before anything is drawn in Designer, the plan's findings boxed in red. drawing_review exposes estimated text envelopes, unmodelled symbols and unchecked native coverage; empty findings do not establish readable layout |
| `schematic sheets` | read | observe | draft | The schematic's sheets |
| `schematic view` | write | session, artifact | draft | Activate a sheet, fit it and bring Designer's window to the front; --output captures the window to a new PNG. Before confirmation, drawing_review lists actual snapshot identities and unenumerated visual geometry; empty findings do not establish a clear sheet. Use --output for independently reopened PNG bytes and target project/sheet/process/window binding; without --output, independent acceptance remains incomplete. Capture verification does not establish font correctness, readability, schematic intent or ERC |
| `session attach` | write | session | draft | Attach to an explicitly selected running Layout process; never launch an application. For Designer, explicitly open a registered closed copy through the current CLI-owned empty session with --project-source-operation-id; arbitrary running-instance takeover is unsupported. Recover Layout ownership only from its original successful start operation. Ownership storage is bounded to 64 exact generations and 256 KiB. The retained runtime host-bootstrap experiment remains disabled. |
| `session close` | write | session, persist | draft | Quit an owned Designer or Layout generation after observing an empty document or explicit --save-project; verify bounded OS exit, retaining pending evidence |
| `session inspect` | read | observe | draft | Whether Designer and Layout are running, and the session this tool recorded (stale after a timed-out call) |
| `session start` | write | session | draft | Start a CLI-owned empty Designer through its authenticated startup host, or start Layout. Designer refuses existing-instance takeover and --project; create or open an authorized project through the same dedicated connection. Layout accepts --project for its board |
| `version` | read | observe | draft | The CLI's version |
